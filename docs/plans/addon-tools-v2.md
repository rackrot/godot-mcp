# Godot MCP addon v2: plugins, input actions, game capture, asset install

## Goal

Add four capabilities to the `godot_mcp` editor addon, asked for by a game project on Godot 4.7 .NET:

1. `enable_plugin` / `disable_plugin`: toggle an addon in the open editor without a restart.
2. `add_input_action`: write `[input]` actions to `project.godot`, with physical-key events and modifiers (Ctrl+P, F1–F5, Alt+digits), plus mouse and joypad buttons.
3. `capture_viewport`: a PNG of the game that `play_scene` (or a person pressing F5) started, which runs in a separate process.
4. `install_asset`: download a Godot Asset Library addon into `addons/` and import it.

The conventions of `addon-mcp-v1.md` hold: handlers return `Variant` with null meaning failure, tool failures go through `tool_error.gd`, paths through `res_paths.gd`, long work through the job guard (D46), and every tool appears in `SKILL.md` (the conformance drift test enforces it). Decisions continue from D51; assumptions continue from A17.

## Definition of done

- [ ] `bun run check` passes, including four new files `tests/editor/{plugins,input-actions,capture,install-asset}.test.ts` against a real `godot-mono --headless --editor` 4.7.2, plus the new `dispatch_probe.gd` checks.
- [ ] `tools/list` returns 29 tools (24 + 5), and `SKILL.md` names each (drift test), documents each new error code, and extends "Code runs in the editor" (D33) for plugin enabling and installed assets.
- [ ] Each slice's acceptance criteria below are met by a test, or by the named operator check where no test can reach (GUI-only behavior).
- [ ] Operator GUI checks, once, in a GUI editor on 4.7.2: (a) `capture_viewport` returns the game frame for a windowed run and for an embedded Game-view run, (b) the Project Settings > Input Map tab shows an action that `add_input_action` wrote, without reopening the editor, (c) `install_asset` installs one real Asset Library addon over the network (TLS, redirect chain) and `enable_plugin` enables it.
- [ ] No `SCRIPT ERROR` in any new test file's editor output.

## Assumptions to verify

- A17 (slice 3 gate): in the headless test editor, after `play_scene` (game run with `--headless`), an `EditorDebuggerPlugin` added by the addon sees an active session within 10 s, `send_message("scene:rq_screenshot", [id])` reaches the game, and the game's `Cannot get an image from a viewport texture` error appears in the editor's captured output (the game inherits the editor's stdio). **If no session ever becomes active headless, stop and report**: the mechanism stays, but its automated coverage shrinks to `NO_GAME` and the operator check.
- A18 (operator): in a GUI editor the reply arrives, its path is in the editor's own `OS.get_temp_path()` (the game inherits the editor's environment), and the PNG is the game frame, for a floating window and for the embedded Game view.
- A19 (slice 2): `ProjectSettings.save()` writes `InputEvent` objects inside an `input/*` Dictionary in a form the game's `load_from_project_settings` reads. Pinned by the slice 2 run-time probe.
- A20 (operator): calling `_update_action_map_editor` on the `ProjectSettingsEditor` node refreshes the Input Map tab. Guarded by `has_method`; if absent, the tool still succeeds and reports `editorRefreshed: false`.
- A21 (slice 4, step 1): the values of `network/connection/network_mode` (expected `0` Offline, `1` Online; read the property hint).
- A22 (slice 4): an `HTTPRequest` child of `EditorInterface.get_base_control()` works in the headless editor against a loopback HTTP server, and against GitHub over TLS in the operator check.
- A23 (slice 4): `DirAccess.rename_absolute` moves a directory from `res://.godot/godot_mcp/staging/…` to `res://addons/<name>` (same filesystem, normally). A cross-device failure gives `WRITE_FAILED` and a cleaned-up stage, never a half-copied addon.

## Decisions

| # | Decision | Why | Rejected |
|---|---|---|---|
| D51 | **Two tools, `enable_plugin` and `disable_plugin`**, one shared handler. Input `name` is the folder under `res://addons/` (nested folders allowed, e.g. `vendor/foo`). The handler builds `res://addons/<name>/plugin.cfg`, checks it with `ResPaths.check_file(path, ["cfg"])`, and passes that **full path** to `set_plugin_enabled`, never the raw name (the setter takes any `res://` string verbatim). Refuses the addon's own `plugin.cfg` (compared case-insensitively with the path `plugin.gd` reports for itself) with `PROTECTED_PATH`: disabling it `memdelete`s the plugin whose handler is on the stack. Already in the wanted state gives `{changed: false}` without calling the setter (`ERR_FAIL_COND`). Before enabling, it parses the cfg with `ConfigFile` and requires a `plugin/script` key, so the common mistakes fail with a message instead of a dialog. After the call it checks `is_plugin_enabled`; a mismatch gives `PLUGIN_FAILED` with the Logger errors since the call (the `import_assets` cursor pattern); when the cfg's script is a `.cs` file the message adds that the plugin needs `build_dotnet` first. It then calls `ProjectSettings.save()` so `editor_plugins/enabled` is on disk when the call returns (the editor's own save is a timer). Result: `{name, path, enabled, changed}`. | Mirrors `play_scene`/`stop_scene` and the requester's names. Disable is the risky verb, so it is its own tool. The editor reports failures only through a dialog, so the tool must check state and read the log. | One `set_plugin_enabled {name, enabled}`: one boolean saves little and reads worse in a tool list. Passing `name` to the setter: a `res://` name would bypass `res_paths`. Relying on the editor's timer save. |
| D52 | **`set_project_setting` keeps refusing `editor_plugins/`**, and its message names `enable_plugin`/`disable_plugin`. | Writing the list doesn't load or unload anything in the running editor, and `_update_addon_config` overwrites it from the editor's own plugin map at the next toggle. | Allowing it |
| D53 | **`get_project_info` gains `plugins`**: `[{name, enabled, version}]` for every `res://addons/**/plugin.cfg` up to 3 folders deep, at most 200, sorted. | An agent needs the names to call D51. Cheap read. | A `list_plugins` tool |
| D54 | **`add_input_action {name, events, deadzone?, append?}`** writes `ProjectSettings` `input/<name>` = `{deadzone, events: [InputEvent…]}` and `save()`, restoring the previous value when the save fails (the `set_project_setting` pattern). **Never touches the editor's `InputMap`**: the editor runs the default map, and the game reads `project.godot` when it starts, so `run_headless` and `play_scene` see the change with no refresh. Best effort, it calls `_update_action_map_editor` on the `ProjectSettingsEditor` node (found with `find_children(…, "ProjectSettingsEditor")`, guarded by `has_method`), because that tab otherwise stays stale until the editor restarts, and a later edit of the same action in the dialog would write its stale copy back. Result: `{name, created, deadzone, events, previous, editorRefreshed}`, where `events` and `previous.events` use the input shape of D55 (an event the shape can't express comes back as `{type: "other", text: var_to_str(event)}`). | Writes what the editor's own Input Map tab writes, and the game is the only consumer that matters | Refreshing the editor `InputMap` (irrelevant to the game, and it holds the editor's own keys); writing `project.godot` text by hand |
| D55 | **Event shape.** An event is a string or an object. A string is Godot's own key syntax, `"Ctrl+P"`, `"F1"`, `"Alt+1"`, and means a physical key. Objects: `{type: "key", key: "P", modifiers?: ["Ctrl"], physical?: true}`; `{type: "mouseButton", button: "left"\|"right"\|"middle"\|"wheelUp"\|"wheelDown"\|"wheelLeft"\|"wheelRight"\|"extra1"\|"extra2", modifiers?}`; `{type: "joypadButton", button: 0..127}`. Every type takes `device?` (default `-1`, all devices, as the editor's dialog). Modifiers are `Ctrl`, `Shift`, `Alt`, `Meta`, and `CmdOrCtrl` (sets `command_or_control_autoremap`), case-insensitive, each at most once. The tool parses the modifiers itself and passes only the last part to `OS.find_keycode_from_string`, which must return a nonzero code with no modifier bits; anything else is `INVALID_VALUE` naming `events[i]` (Godot's parser silently drops unknown modifier words). A physical key sets `physical_keycode` and leaves `keycode` 0; `physical: false` does the reverse. At most 32 events. | Physical keys are what the requester needs (layout-independent debug keys). One string form covers the common case; the object form adds mouse and joypad. | `joypadMotion` (deferred: axis plus direction plus deadzone semantics, and not requested); exposing raw `InputEvent` properties; reusing the value codec (it refuses Objects by design, D35) |
| D56 | **Replace by default, `append: true` to add.** Replace sets the full event list and the deadzone (default 0.2 for a new action; a replaced action keeps its deadzone unless one is given). Append adds only events that no existing event matches exactly, so repeating a call changes nothing. The match compares the event class and every field D55 sets (code, physical flag, modifiers, button, device); `InputEvent.is_match(…, true)` is **not** used, because whether it compares `device` is unverified. Built-in `ui_*` actions may be replaced or appended to, as in the editor. Removing an action is out of scope; `events: []` empties one. | A full list is idempotent and easy to reason about; append covers "also bind F5 to this". | Append by default (repeats duplicate); a separate remove tool (not requested) |
| D57 | **`set_project_setting` refuses `input/`** with `PROTECTED_SETTING`, naming `add_input_action`. Today it accepts a JSON Dictionary there, which can only carry JSON leaves, so events would be written as plain Dictionaries the game can't load. `input_devices/` is a different prefix and stays allowed. | Removes a way to write a broken action | Leaving it |
| D58 | **`capture_viewport` uses the engine's own `scene:rq_screenshot` message** through an `EditorDebuggerPlugin` (`capture_debugger.gd`) that `plugin.gd` adds with `add_debugger_plugin` and removes in `_exit_tree`. It sends `scene:rq_screenshot [id]` to the first active session, with ids from 2^40 up (never colliding with `GameViewDebugger`'s ids from 0), and claims `game_view:get_screenshot` replies whose id it issued (`_has_capture("game_view")`; other ids return false and stay with the Game view). No runtime script, no autoload, no change to the user's project. Works for any debug run started from this editor: `play_scene`, F5, the embedded Game view. | The game already implements the capture, HDR-to-sRGB conversion included, and only the pixels' path crosses the debugger channel (no 8 MiB limit). | An autoload plus `EngineDebugger.register_message_capture` (needs a project autoload and code that ships in exports); `EditorPlugin._run_scene` to inject args (can't add a script); the embedded Game view's own screenshot (C++-only callback, needs embedding, GUI only); `DisplayServer.screen_get_image` (whole screen, needs the window on top) |
| D59 | **Capture flow and failures.** Not playing and no active session gives `NO_GAME` at once. Playing but no active session yet waits (the debugger connects shortly after `play_scene` returns). No reply within `timeoutSec` (default 10, 1–60) gives `CAPTURE_TIMEOUT`; its message says a game run with `--headless` (see `editor/run/main_run_args`) has no renderer, and a game paused at a breakpoint may not answer. The reply's path must be a regular file directly in the editor's `OS.get_temp_path()`, named `scr-<digits>.png`, not a link, at most 64 MB, starting with the PNG signature; otherwise `CAPTURE_FAILED` (a game on another machine, or a game that sends a crafted path, so the editor never copies an arbitrary file into the project). The temp file is removed after the copy. The handler stays in the FIFO with its budget set to `timeoutSec + 10 s`. | Bounded waits, and a path from project code is treated as untrusted | Holding no budget; trusting the reply path |
| D60 | **Capture output.** Default path `res://.godot/godot_mcp/captures/capture-<unix ms>.png`; the addon keeps the newest 20 files it named there and deletes older ones. Optional `path`: a new `res://….png` checked by `ResPaths.check_new_file(path, ["png"])`, refused under `addons/godot_mcp/`, then `update_file`. Result: `{path, absolutePath, width, height, bytes}` and, unless `inline: false`, one MCP `image` content block: the PNG scaled to at most 1568 px on the long side, re-encoded as PNG, or JPEG at quality 0.85 when the PNG exceeds 2 MB. | `.godot/` is already gitignored (`.godot/godot_mcp/.gitignore`), the editor never imports it, and it is inside the workspace, so the agent can open `absolutePath` with its own file tools without a permission prompt. An inline image lets the model see the frame in one call. | `user://` (outside the workspace); writing captures into `res://` by default (each import adds a `.import` file and a texture); returning base64 inside `structuredContent` (it is copied into the text block, doubling the size) |
| D61 | **Extra content blocks (transport contract).** A handler may return a reserved key `_content`, an Array of MCP content blocks. `McpServer._call_tool` removes it from `structuredContent`, builds the text block from the rest, and appends the blocks after it. Only `{type: "image", data: <base64>, mimeType: "image/png"\|"image/jpeg"}` is accepted; anything else makes the call `INTERNAL`. The 4 MB response cap still applies. | The smallest change that lets a tool return an image | An `outputSchema` (D36 rejected it); a second response format |
| D62 | **`install_asset {assetId, version?, sha256?, overwrite?, allowNativeCode?, timeoutSec?}` installs only from the Asset Library API by id. No raw URL in v2.** The API record supplies provenance (title, license, `godot_version`, `download_commit`) and the download URL. `version`, when given, must equal the record's current `version_string` (else `VERSION_MISMATCH`, naming the current one); older versions are not offered. `sha256`, when given, must match the download (else `HASH_MISMATCH`); so must a non-empty `download_hash` that is 64 hex digits. The format of `download_hash` is **unverified** (empty in every sampled record), so any other non-empty value adds a warning and is not compared. The tool always reports the SHA-256 it computed. | A raw URL would make the tool a fetch-and-install-anything primitive. The id ties the code to a moderated listing. | A raw `url` (open question 1); resolving older versions through `/asset/edit` (deferred) |
| D63 | **Source restrictions.** `https` only, port 443, no userinfo. Hosts are matched exactly against a fixed list: `godotengine.org` (the API only), `github.com`, `codeload.github.com`, `release-assets.githubusercontent.com`, `objects.githubusercontent.com`, `gitlab.com`. `HTTPRequest` runs with `max_redirects = 0`; the handler follows at most 5 redirects itself, checking each `Location` against the same rules before connecting. The API record must have `type == "addon"` and a `godot_version` with the editor's major version (else `INCOMPATIBLE_ASSET`); a newer minor version adds a warning. When the editor is in offline network mode the tool refuses with `NETWORK_OFFLINE`. The editor's HTTP proxy settings are applied. **Test seam:** the environment variable `GODOT_MCP_ASSET_LIBRARY_URL` replaces the API base and adds that one origin to the host list; plain `http` is accepted only when its host is `127.0.0.1`. | Covers every host in the sample, checks every hop, and respects the user's offline choice. An environment variable doesn't travel with a cloned project, unlike a `project.godot` key. | Following redirects inside `HTTPRequest` (it would connect to an unchecked host); host suffix matching; a `project.godot` override key; shelling out to `curl` (an external dependency with no gain) |
| D64 | **Limits.** API response 1 MB. Download 64 MiB (`body_size_limit`). Zip: at most 20,000 entries, 64 MiB per file uncompressed, 256 MiB in all, and a file whose declared size is over 100 times its compressed size and over 1 MiB is refused. Every limit is checked from the archive's central directory before anything is extracted. `timeoutSec` default 120, 1–540; the request budget is `timeoutSec + 10 s`. | `ZIPReader.read_file` allocates the declared size, so the declared sizes must be checked first, in GDScript | Trusting `ZIPReader`; extracting first and measuring after |
| D65 | **Zip index and entry rules** (`zip_index.gd`). The tool parses the end-of-central-directory record and the central directory itself, reading each entry's name, flags, method, sizes and external attributes. It refuses: zip64 records, encrypted entries, methods other than stored and deflate, symlink entries (Unix mode `0xA000` in the external attributes), names that are not valid UTF-8, names with `\`, `:`, a control character, a leading `/`, or an empty, `.` or `..` segment, and two names equal after lowercasing. Its name list must equal `ZIPReader.get_files()` exactly, so both parsers agree on what is in the archive. Any violation refuses the whole install with `ZIP_UNSAFE` before a byte is written outside the stage. | Zip-slip and zip-bomb protection that doesn't depend on `ZIPReader` internals | Validating only `get_files()` (no sizes or modes); best-effort skipping of bad entries (a partial addon is worse than none) |
| D66 | **Only the `addons/` subtree is installed.** All entries must share one optional top folder (GitHub and GitLab archives add `<repo>-<commit>/`); the subtree is `addons/` at depth 0 or 1. Each first folder under it is one addon. None gives `INCOMPATIBLE_ASSET`. An addon named `godot_mcp` (any case) refuses the install with `PROTECTED_PATH`. Files outside the subtree (`project.godot`, `override.cfg`, demo scenes, `.godot/`) are never written. | `override.cfg` and `project.godot` at the archive root would change the project's settings and autoloads; the editor's own installer lets a person deselect them, an agent can't. | Installing the whole archive; the editor's `EditorAssetInstaller` (GUI only) |
| D67 | **Native code refused by default.** Any `.gdextension`, `.gdnlib`, `.so`, `.dll`, `.dylib`, `.a`, `.wasm`, or a path through a `.framework` or `.xcframework` folder gives `NATIVE_CODE`, listing up to 10 paths, unless `allowNativeCode: true`. A `.cs` file sets `needsDotnetBuild: true` in the result. | A `.gdextension` loads its library at the next filesystem scan, before any enable, and any later scan (even a focus change) would load it, so the files must never be written without consent. | Writing them and skipping our scan (the editor scans by itself); refusing C# (it runs only after `build_dotnet` and a deliberate enable) |
| D68 | **Overwrite policy and staging.** Download to `res://.godot/godot_mcp/downloads/<random>.zip`, extract to `res://.godot/godot_mcp/staging/<random>/` (the editor never scans `.godot/`), checking each written file's size against the index. An existing `res://addons/<name>` gives `FILE_EXISTS` unless `overwrite`; with `overwrite`, a plugin under it that is enabled gives `PLUGIN_ENABLED` (call `disable_plugin` first: replacing a running plugin's scripts is the reload class that crashed `validate_script`). `res://addons`, the target and every path component must not be links. Then, per addon: move the old folder to `res://.godot/godot_mcp/backups/<name>-<unix ms>/` (the newest 5 backups are kept), move the staged folder into place, and on any failure move everything back. The download and stage are removed in every outcome. Plugins are **never** enabled by the install. | The editor never sees half an addon; overwrite is a folder swap, so files dropped by the new version are gone; the old version stays recoverable | Merging into the existing folder; enabling plugins automatically |
| D69 | **`install_asset` is a job** (D46): `_busy` gives `PROJECT_BUSY` to other jobs and to `play_scene`. It hands the FIFO back at the start (`extend_budget(…, true)`), like `run_headless`, because almost all its time is network I/O; the final scan is the same `EditorFileSystem.scan()` the editor runs by itself when files change. The scan-and-wait code moves out of `_import` into one shared helper used by both `import_assets` and `install_asset`. Result: `{ok, assetId, title, versionString, godotVersion, license, downloadUrl, finalUrl, sha256, bytes, addons, plugins, files, needsDotnetBuild, backups, warnings, diagnostics, errorCount, warningCount, truncated}`. Cancel stops the download (`cancel_request` removes the partial file), removes the stage, and rolls back a swap in progress. | The editor stays usable during a slow download | Holding the FIFO (other tools would fail after 30 s behind a download); copying `_import` |
| D70 | **D33 amendment.** `enable_plugin` runs the plugin's `_enter_tree` and `_enable_plugin`; `disable_plugin` runs `_disable_plugin` and `_exit_tree`. `install_asset` brings remote code into the project: with `allowNativeCode` its native libraries load at the next scan, which the install then skips (loading a GDExtension reloads every editor script and cancels the running handlers, verified on 4.7.2); its `@tool` scripts run when a scene that uses them opens; its plugin runs when enabled; its C# compiles into the game at the next build. The archive's `*.import` files (any case) are never written: their `[params]` (`import_script/path`, `nodes/root_script` and others) name scripts the editor runs while it reimports, which the install's own scan would do before the call returns, and a probe showed such a script writing files and enabling its plugin. The editor writes default import files instead. `capture_viewport` runs no project code beyond the game already running. The bearer token stays the only boundary. | Honest threat model | Calling the restrictions a sandbox |

## Reuse analysis

- **Existing patterns reviewed:** provider classes with `tools()` (`project_tools.gd`, `editor_tools.gd`, `job_tools.gd`); `ResPaths.check_file`/`check_new_file`; `ToolError.fail`; `set_project_setting`'s set-save-restore sequence; the Logger cursor (`_log.seq()`, `errors_since`) from `import_assets`; `Request.next_frame`/`extend_budget` and `JobTools._wait`; the `_busy` job guard; `_import`'s scan-and-wait; helper modules beside tools (`job_runner.gd`, `msbuild_parser.gd`, `dotnet_project.gd`); the `setup_probe.gd`/`dispatch_probe.gd` runners; the harness's `startEditor({env})`.
- **Chosen approach: Extend**, with one **Extract**. Plugin and capture tools extend `editor_tools.gd`; `add_input_action` extends `project_tools.gd` and reuses its save-and-restore; `install_asset` extends `job_tools.gd` and its `_busy`/`_wait`. The scan-and-wait in `_import` is extracted into a helper for both import paths (the only place copying would otherwise exceed the 20% rule). New modules only where nothing exists: `input_events.gd` (event build and encode), `capture_debugger.gd` (the `EditorDebuggerPlugin` subclass, which must be its own class), `asset_installer.gd` (fetch, verify, stage, swap), `zip_index.gd` (central directory parse).
- **Duplication risk: Low.** No parallel tool, job or validation flows.

## Slices

Order by risk, cheapest first: 1 → 2 → 3 → 4. Each slice is one commit, updates `SKILL.md` (tool table, errors, limits, D70 text) and, where it adds a fact an agent needs on first contact, `INSTRUCTIONS` (≤2,000 characters; about 700 today). The check for every slice is `bun run check`, which runs the drift test. Each slice's own test file is the targeted check while iterating; rerun the whole suite only before the commit.

### Slice 1. `enable_plugin`, `disable_plugin`, `get_project_info.plugins` (coder; mechanical with two judgment points)

- **Files:** `tools/editor_tools.gd` (handlers; takes the addon's own cfg path from `plugin.gd`), `tools/project_tools.gd` (`plugins` in `get_project_info`; the D52 message), `plugin.gd` (wiring), `SKILL.md`, `fixtures/gd/addons/marker/{plugin.cfg,marker.gd}` (an `@tool` EditorPlugin whose `_enter_tree` writes `res://marker_state.txt` = `enter` and whose `_exit_tree` writes `exit`), `fixtures/gd/addons/broken_plugin/{plugin.cfg,broken.gd}` (a parse error), `fixtures/gd/addons/no_script/plugin.cfg` (no `script` key), `tests/editor/plugins.test.ts`.
- **Depends on:** nothing.
- **Acceptance criteria:**
  - `enable_plugin {name: "marker"}` gives `changed: true`; `marker_state.txt` reads `enter`; `project.godot` on disk lists `res://addons/marker/plugin.cfg` when the call returns. A second call gives `changed: false` and the log gains no error.
  - `disable_plugin` gives `exit` and removes the entry from disk; a second call gives `changed: false`.
  - `get_project_info.plugins` lists `marker`, `broken_plugin`, `no_script` and `godot_mcp` with the right `enabled` flags.
  - `godot_mcp` (and `GODOT_MCP`) is refused with `PROTECTED_PATH` by both tools, and the server still answers afterwards.
  - `broken_plugin` gives `PLUGIN_FAILED` with a diagnostic naming `broken.gd`; `no_script` gives `PLUGIN_FAILED` before the editor is asked; `missing` gives `FILE_NOT_FOUND`; `../x`, `a\\b` and a symlinked folder give `INVALID_PATH`.
  - `set_project_setting editor_plugins/enabled` still gives `PROTECTED_SETTING`.
- **Cheapest check:** `bun test tests/editor/plugins.test.ts`.
- **Rerun when:** `editor_tools.gd`, `plugin.gd` or the fixtures change.

### Slice 2. `add_input_action` (coder-high; the event shape needs judgment)

- **Files:** `input_events.gd` (parse D55 into events; encode events back), `tools/project_tools.gd` (handler; D57 refusal), `SKILL.md`, `fixtures/gd/input_probe.gd` (extends `SceneTree`; for each action named in its user args prints one JSON line with `InputMap.action_get_deadzone` and each event's class, `physical_keycode`, `keycode`, modifier flags, `device` and `button_index`, plus whether a synthetic `InputEventKey` with `physical_keycode = KEY_P`, `ctrl_pressed = true`, `device = 0` matches the action through `InputMap.event_is_action`), `tests/editor/input-actions.test.ts`.
- **Depends on:** nothing (the tests use `run_headless`, already shipped).
- **First step:** A19. Write one action, run `input_probe.gd` through `run_headless`, and read it back. If the game doesn't see it, stop and report.
- **Acceptance criteria** (behavior is asserted through `input_probe.gd`, not through the text of `project.godot`):
  - `debug_toggle` with `["Ctrl+P"]`: the game sees one physical-key event, `KEY_P` with Ctrl only, device -1, deadzone 0.2, and the synthetic device-0 Ctrl+P matches.
  - `F1`…`F5` and `Alt+1`…`Alt+5` as five actions: the game sees each with the right code and modifier.
  - Object forms: a `mouseButton` `right` with `Shift`, and a `joypadButton` 0, are seen with the right `button_index`. `physical: false` sets `keycode` and leaves `physical_keycode` 0. `CmdOrCtrl` sets `command_or_control_autoremap`.
  - Replace: a second call with `["F6"]` leaves only F6, returns `created: false` and `previous` holding the Ctrl+P event in the input shape; the deadzone is kept. Append: `append: true` with `["F6", "F7"]` adds only F7.
  - Refusals: `"Hyper+P"`, `"Ctrl+Ctrl+P"`, `"Ctrl+"`, `"Ctrl+NoSuchKey"`, a `joypadButton` 128, 33 events, a bad action name, `deadzone` 1.5 (schema) all fail, and `project.godot` is unchanged afterwards.
  - `set_project_setting input/foo` gives `PROTECTED_SETTING`; `input_devices/pointing/emulate_touch_from_mouse` is still settable.
  - `editorRefreshed` is a boolean. Its effect on the Input Map tab is operator check (b).
- **Cheapest check:** `bun test tests/editor/input-actions.test.ts`.
- **Rerun when:** `input_events.gd`, `project_tools.gd` or `input_probe.gd` change.

### Slice 3. `capture_viewport` (coder-high; gated)

- **Files:** `capture_debugger.gd` (`EditorDebuggerPlugin`: `_has_capture("game_view")`, `_capture`, `request(id)`, pending replies by id), `capture_store.gd` (D59 path checks, the copy, the rotation, the inline image), `tools/editor_tools.gd` (handler), `plugin.gd` (`add_debugger_plugin`/`remove_debugger_plugin`), `mcp_server.gd` (D61), `tests/editor/probes/dispatch_probe.gd` (D61 checks), `tests/editor/probes/capture_probe.gd` (D59/D60 checks outside the editor), `SKILL.md`, `tests/editor/capture.test.ts`.
- **Depends on:** nothing; D61 is the slice's first code step, since the image block needs it.
- **First step, the gate (A17):** a throwaway handler in a temp copy plays the main scene headless, waits for an active session, sends `scene:rq_screenshot`, and greps the editor output for the game's error. Record the delay until the session is active. **If no session becomes active, stop and report.**
- **Acceptance criteria:**
  - D61, in `dispatch_probe.gd` with a fake provider: an image block is appended after the text block, `_content` is absent from both `structuredContent` and the text, and a `_content` holding a non-image block makes the call `INTERNAL`.
  - D59/D60, in `capture_probe.gd` (a PNG the probe writes into `OS.get_temp_path()` stands in for the game's file): a valid reply is copied to the default folder and the temp file removed; a 21st capture deletes the oldest; a path outside the temp dir, a wrong name, a symlink, and a non-PNG file each give `CAPTURE_FAILED` and leave the source alone; a 4000×3000 PNG becomes an inline image at most 1568 px on the long side; a noise image whose PNG exceeds 2 MB becomes a JPEG block.
  - In the editor: with nothing playing, `NO_GAME` within 1 s. After `play_scene` (headless), `capture_viewport {timeoutSec: 3}` gives `CAPTURE_TIMEOUT`, and the editor output then holds the game's `Cannot get an image from a viewport texture` line, which proves the request reached the game. `stop_scene` follows.
  - A `game_view:get_screenshot` reply with an id below 2^40 is not claimed (probe: `_capture` returns false).
  - Path rules: a `path` that exists gives `FILE_EXISTS`; one under `addons/godot_mcp/` gives `PROTECTED_PATH`; `res://x.jpg` gives `INVALID_PATH`.
  - Pixels are operator check (a): a windowed and an embedded run each return the frame, and the image block shows in Claude Code.
- **Cheapest check:** the two probes (seconds), then `bun test tests/editor/capture.test.ts`.
- **Rerun when:** `mcp_server.gd` changes (also rerun `dispatch.test.ts` and `conformance.test.ts`), or any capture file changes.

### Slice 4. `install_asset` (coder-max; security review before merge)

- **Files:** `asset_installer.gd` (API fetch, hop-checked download, hash, stage, swap, rollback), `zip_index.gd` (D65), `tools/job_tools.gd` (handler; the extracted scan helper; `import_assets` switched to it), `SKILL.md`, `tests/editor/zip.ts` (a small zip writer over `node:zlib` `deflateRawSync`: stored and deflated entries, arbitrary names, external attributes, and declared sizes that may lie), `tests/editor/install-asset.test.ts` (a `Bun.serve` on 127.0.0.1 serving API records, zips and redirects; the editor started with `GODOT_MCP_ASSET_LIBRARY_URL`).
- **Depends on:** slice 1 (`PLUGIN_ENABLED` uses the plugin check; a test enables the installed plugin).
- **First step:** A21 (read the `network_mode` hint) and A22 (one loopback `HTTPRequest` from the headless editor). Then extract the scan helper and rerun `jobs.test.ts` before adding anything, so a regression in `import_assets` shows up alone.
- **Acceptance criteria:**
  - Happy path: a GitHub-style zip (`repo-abc/addons/hello/{plugin.cfg,hello.gd}`, `repo-abc/README.md`, `repo-abc/project.godot`, `repo-abc/override.cfg`) installs `res://addons/hello` only; a tree diff of the project (ignoring `.godot/`) shows nothing else; `sha256` equals the one the test computed; `plugins` is `["hello"]`; `enable_plugin hello` then succeeds; `.godot/godot_mcp/{downloads,staging}` are empty.
  - Zip-slip and entry rules: each of `addons/x/../../evil.gd`, `/addons/x/a.gd`, `addons\\x\\a.gd`, `addons/x/./a.gd`, a symlink entry, `Addons/X/a.gd` beside `addons/x/a.gd`, a name with a control character, and an encrypted entry gives `ZIP_UNSAFE`, and the project tree is unchanged.
  - Zip bomb: an entry declaring 2 GB uncompressed gives `ZIP_UNSAFE` before extraction; the editor answers `get_project_info` right after, and its `VmHWM` (peak RSS, `/proc/<pid>/status`) grew by less than 256 MB across the call. A growth bound, not an absolute one, because the .NET editor's baseline RSS is not known.
  - Size: a 65 MiB body with `Content-Length`, and the same chunked, each give `TOO_LARGE`, with no partial file left.
  - Sources: an API record whose `download_url` is on another host, and a redirect to another host (the test server records that it was never contacted, since the host is not loopback), give `UNTRUSTED_SOURCE`; an `http://` download URL other than the test origin is refused.
  - Record checks: `type: "project"` and `godot_version: "3.5"` give `INCOMPATIBLE_ASSET`; `version` other than the current gives `VERSION_MISMATCH`; a wrong `sha256` and a wrong non-empty `download_hash` give `HASH_MISMATCH`; a zip with no `addons/` gives `INCOMPATIBLE_ASSET`; `addons/godot_mcp/...` in the zip gives `PROTECTED_PATH`.
  - Native code: a zip with `addons/n/n.gdextension` gives `NATIVE_CODE` and writes nothing; with `allowNativeCode: true` it installs (the scan logs the missing library, which shows in `diagnostics`). A `.cs` file sets `needsDotnetBuild`.
  - Overwrite: an existing `addons/hello` gives `FILE_EXISTS`; `overwrite: true` replaces it (a file only in the old version is gone) and returns the backup path, which holds the old files; with `hello` enabled, `PLUGIN_ENABLED` and nothing changes.
  - Jobs: during a `run_headless` of `hang.gd`, `install_asset` gives `PROJECT_BUSY`; during a slow download (the server dribbles bytes) other editor tools answer, and cancelling through an SDK `AbortSignal` returns `CANCELLED` and leaves no download, stage or partial addon.
  - `import_assets` behaves as before (its existing tests pass unchanged).
  - Real network is operator check (c).
- **Security review:** before the commit, run `/security-review` (or the second-opinion skill's diff mode) on the slice diff, focused on D63–D68.
- **Cheapest check:** `bun test tests/editor/install-asset.test.ts`, plus `jobs.test.ts` after the extraction.
- **Rerun when:** any slice-4 file changes; `jobs.test.ts` whenever the scan helper changes.

## Risks and rollback

| Risk | Mitigation |
|---|---|
| A17 fails: no debugger session in the headless editor | The slice 3 gate stops work; the design stays (it is GUI-correct) and coverage falls back to `NO_GAME`, the probes and the operator check |
| `scene:rq_screenshot` or `game_view:get_screenshot` changes in a later Godot | Messages are engine-internal; pinned to 4.7.2 by CI; a changed reply shape gives `CAPTURE_TIMEOUT`, not a crash. Recheck on each Godot bump. |
| `_update_action_map_editor` is internal and may vanish | `has_method` guard; `editorRefreshed: false`; the action is still written |
| A plugin's `_enter_tree` or `_exit_tree` crashes or blocks the editor | Same as any human toggle; D70 documents it |
| Remote code: a malicious or compromised asset | Id-only sources, host allowlist per hop, hash reporting and pinning, `addons/`-only, native code refused by default, no auto-enable, backups; D70 states what still runs |
| Mutable `Custom` URLs (`refs/heads/main`) install different code under the same version | `sha256` reported every time; pin with `sha256`; SKILL.md says so |
| GDScript zip parsing bugs | `ZIPReader.get_files()` cross-check; refusal on any doubt; crafted-zip tests |
| Overwrite of an addon the open scenes use | `PLUGIN_ENABLED` covers enabled plugins; a backup keeps the old folder; documented |
| Network flakiness in CI | No test uses the network; loopback server only |
| `install_asset` detached: another tool edits the project during the scan | The same as a person editing during an editor scan; only one job runs |
| Rollback | Each slice is one commit, so `git revert`. Consumer touchpoints: `project.godot` (`editor_plugins/enabled`, `input/*`), `res://addons/<name>`, `.godot/godot_mcp/{captures,backups}`. |

- A raw-URL source for `install_asset`, and older versions through `/asset/edit` (open questions 1 and 4).

## Open questions

Resolved 2026-10-31: the user accepted every recommended answer below. Slices run 1 → 4, one PR each with a reviewer pass; slice 4 also gets a security audit.

1. **Raw URL in `install_asset`?** Recommended: no, Asset Library id only (D62). If needed later, accept only a pinned `https://github.com/<o>/<r>/archive/<40-hex>.zip` with a required `sha256`.
2. **Native code (GDExtension) refused by default?** Recommended: yes, `NATIVE_CODE` unless `allowNativeCode: true` (D67), because the editor loads a `.gdextension` at the next scan with no enable step.
3. **A CI lane that renders pixels (Xvfb plus Mesa, game run without `--headless`)?** Recommended: not now. The operator check covers pixels; add the lane if capture regresses. Xvfb is not installed locally either.
4. **Older asset versions through `/asset/edit/<id>`?** Recommended: defer. `version` only pins the current `version_string` in v2.
5. **Download hosts beyond GitHub and GitLab (Codeberg, self-hosted)?** Recommended: fixed list in v2 (D63); add a user-edited `godot_mcp/install_asset/extra_hosts` key only when a needed asset lives elsewhere.
6. **Removing input actions?** Recommended: defer; `events: []` empties an action.
7. **Tool name `capture_viewport` or `capture_game`?** It captures the running game, not an editor viewport. Recommended: keep the requester's name and say "running game" in the description.

Unverified, carried as assumptions or risks rather than settled: A17–A23 above; whether `ProjectSettings.save()` keeps `InputEvent` objects loadable (A19); the `network_mode` values (A21); the `download_hash` format (D62).
